# 晋江登录：为什么走 WAP

CPYOS 使用晋江手机版 WAP 登录（`m.jjwxc.net/login/wapLogin`），**不使用 App API 登录接口**。这是产品与风控约束，不是实现偷懒。

## 会话共存

用户已确认：手机浏览器/网页端与 App 端的登录状态可以长期共存。WAP 登录会话与手机端会话是两套体系，设备上的 WAP 登录不会把手机端顶下线；这正是我们要的形态——设备是一个额外阅读终端，而不是替换手机。

## 图形验证码（未解决）

App API 登录目前会被服务端要求图形验证码：

- 登录返回 `6018`（请校验验证码）后，申请设备验证码会得到 `2021: 异常请求，缺少前置步骤或操作超时`；
- 用户确认手机端登录是「图形验证码 + 邮箱验证码」两段；
- 墨水屏没有 JS 引擎，也没有可用的图形验证码交互，**这个问题目前没有解决**，所以 App API 登录路径不可用。

因此不要把 App API 登录重新接回设备，也不要为了“再试一次”反复登录——每次失败都可能增加账号风控计数。

## 当前登录路径

- WAP 登录表单（14 个字段）由 `JjwxcWapLogin` 构造；设备验证码路径保留。
- WAP 登录目前没有图形验证码（用户在本机浏览器完成 WAP 登录时确认）。设备端第一次真实登录仍需用户亲自操作并观察串口；如果服务端将来也对 WAP 加图形验证码，需要新的方案，不能靠重试绕过。
- 登录后的 cookie jar 持久化在设备上；账号、密码、token、cookie 不写日志、不进仓库。
- 需要复用会话做开发时，从设备导出 cookie，不要在主机端重新登录。
