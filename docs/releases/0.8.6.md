# 脆皮鸭 CPYOS 0.8.6

Read Pico `0.8.6-rp` · Metalio E-INK4 Plus `0.8.6-e4p`

本次把 0.8.4 现场反馈的四个症状（设置崩溃、文字空白/缺字、Wi-Fi 全部失败）按**代码结构**修掉，
并让两台设备的失败都能自己说明原因——用户不需要串口日志。

## 崩溃

- **崩溃屏零分配**：它存在的意义就是报告堆失败，却曾用 `std::string`/`std::vector` 组装内容而二次崩溃。
  现在全部定长缓冲；`PNC-04` 会带上**失败分配的大小**与当时的内部堆余量（`new=…B heap=…K/…K`）。
  看门狗（任务看门狗/欠压）重启也会进入崩溃屏并写 `crash_report.txt`。
- **设置页**：不再同时持有两张 ~18 KB 的设置表（0.8.4 的 `operator new failed` 根因）；分类表直接由源行构建。
- **活动创建**：所有产品入口改用 no-throw 分配，失败显示提示而不是 abort。
- **Plus 首次具备崩溃屏**：C++ 失败钩子、开机故障环、activity/stage/heap 记录与 panic 启动路由全部接上。
- **PDF**：页文本提取的 16 KB 连续内部缓冲改为 PSRAM 优先、失败降级为"无文本页"。

## 字体

- 网络回收后的字体会被**配对归还**，且该策略是两个 main 共享的组件（Plus 此前只有回收、没有归还）。
- 部分建成/阅读面失败的补充字体不再被记成"健康"，会重试；看门狗有 1s→60s 退避，失败不重绘。
- 缺字提示不再被无关字体包抑制（冥 U+51A5 这类字会正确提示安装中文包）。
- 字体分配不再在 PSRAM 失败时静默占用内部 RAM（把内部堆留给 Wi-Fi/TLS）。

## 网络

- **每次加入前必定先启动站点**，"在已停止的站点上 join"不再是可达状态；失败后驱动会做一次有界重启再重试。
- 失败原因直接显示：未找到网络 / 连接超时 / 请检查密码 / 内存不足 / 驱动拒绝，不再一律「通用故障」。
- 后台缓存持有站点时，界面退出不再拆掉别人的连接（"重缓存静默回首页"的那个半因）。
- 时光同步的暂停/恢复按会话配对，时钟不再整场不校时。

## 其它

- 等待卡/消息卡零分配；设置写失败会弹窗「无法写入存储卡」。
- 队列停止显示「缓存已停止 · 点按重试」，不再误报"服务端错误"。

## 升级

- 本次新增语言键（1885 键）：**请与固件一并更新数据分区**（网页刷机或完整安装；OTA 会带数据包）。
- 分区布局、PDF 引擎契约未变；Read Pico 可 OTA，Plus 首次安装仍用官网完整包。
