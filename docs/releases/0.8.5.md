# 脆皮鸭 CPYOS 0.8.5

Read Pico `0.8.5-rp` · Metalio E-INK4 Plus `0.8.5-e4p`

本次是**安装渠道修复**：固件行为、分区布局、数据包内容与格式都与 0.8.4 相同。

## 修复：Plus 的一键网页安装一直缺文件

从 0.8.1 起，每个 Release 都发布 Plus 的固件与数据包，却**没有**发布
`cpyos-plus-<ver>-partition-table.bin`。后果不是少一个下载项：

- 官网的「选择 Metalio E-INK4 Plus → 网页刷机」需要由发布材料生成 `flash-plus.json`
  （分区表 + 两个应用槽 + 六个数据包）。缺分区表时站点构建只打印一行就跳过，于是
  `downloads/<ver>/flash-plus.json` 一直 404，网页一键安装不可用；
- README 的手动完整安装明确让用户下载同一个文件，同样落空。

## 修复方式

- Plus 发布作业现在把同一次构建产出的 `partition/build_shell/partition_table/
  partition-table.bin` 随版本发布为 `cpyos-plus-<ver>-partition-table.bin`。
- 站点生成器不再「缺资产就跳过」：**只要发布了 Plus 固件，缺分区表或缺
  `data_manifest_plus.txt` 就让站点构建失败**（只有 Read Pico 的版本仍正常跳过）。
  这条从 0.8.1 静默存活了四个版本，以后不可能再无声发生。
- `test_plus_flash_manifest.py` 原先在 HEAD 上就是红的（三组夹具还在等一个早已移除的
  「别名查找」）；已按现行契约重写（manifest 最后一列就是文件名），并补上缺表 / 缺清单 /
  缺数据包必须失败、纯 Read Pico 版本必须跳过四类用例。

## 包含 0.8.4

如果你还在 0.8.3：0.8.4 修的是**两个设备的同名数据包在同一个 Release 里互相覆盖**
（`i18n_pack.dat` 与 `web_pack.dat` 两目标字节不同、大小相同）。现在 Plus 的数据包一律以
`plus-` 前缀发布。Plus 若在 0.8.3 之后手工刷过数据分区、语言已回退英文，请用本版数据包
（或网页刷机）重刷一次数据分区；书籍、设置、进度不受影响。

## 升级建议

- Read Pico：与 0.8.4 无差别，可 OTA。
- Plus：应用可用 CloudZao 更新；**首次安装**请用官网网页刷机或
  `ports/metalio_plus/scripts/flash_metalio_plus.py --layout port-ota --full-install`，
  现在两者需要的分区表都会随版本提供。
- 不需要整片擦除；数据包与 PDF 引擎契约未变。
