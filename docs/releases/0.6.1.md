# 脆皮鸭 CPYOS 0.6.1

修复“检查更新卡住/失败”，并让 OTA 清单走可用的镜像线路。基于 0.6.0，面向 **Read Pico（小纸 Pico，RDP-G01-W）**。

## 修复

- **检查更新不再被单个镜像拖死**：依次尝试 GitHub Pages、ghfast、gh-proxy 与直连 GitHub 的同一份清单，单次请求 12 秒上限；不再对七条线路逐一探测。
- **清单请求有 12 秒上限**：不会再让一个挂起的 TLS 连接阻塞 UI 40 秒以上。
- **数据包清单走同一线路**：`readpico-packs.txt` 与 app 清单使用同一主机；数据包下载仍然只下载变化的 blob。
- **失败提示**：如果所有线路都不可达，检查更新会正常结束并显示失败，而不是卡住；连接 Wi-Fi 不代表该网络能访问 GitHub，请确认网络可访问 GitHub / 镜像 / Pages 中至少一个。

## 升级说明

- 0.6.0 可直接设备 OTA；数据包与 0.6.0 相同，不需要完整安装。
- 0.2.1 及更早版本仍请用官网网页刷机升级一次。
- 本次没有改分区表、数据包布局或语言包键集合。

## English

Fixes a hanging or failing update check and routes the OTA manifest through a reachable mirror. Based on 0.6.0, for **Read Pico (RDP-G01-W)**.

**Fixes.** The check tries the Pages copy, ghfast, gh-proxy and direct GitHub in order, with a 12 s limit per request instead of probing seven routes. Every manifest request has a 12 s timeout, so a dead TLS connection can no longer block the UI for 40 s. `readpico-packs.txt` is fetched from the same host as the app manifest; only changed data blobs are downloaded. If no route is reachable, the check ends with a normal failure instead of hanging; a connected Wi-Fi network does not guarantee access to GitHub, so verify the network can reach at least one of GitHub, a mirror or Pages.

**Upgrade.** 0.6.0 can use device OTA directly. The data packs are unchanged from 0.6.0; no full install is needed. Devices on 0.2.1 or older still need the web flasher once. This release does not change the partition table, data layout or language key set.
