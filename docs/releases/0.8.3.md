# 脆皮鸭 CPYOS 0.8.3

Read Pico `0.8.3-rp`

本次是**稳定性版本**：0.8.1/0.8.2 上可以稳定复现的两类崩溃被消除，崩溃本身也第一次变成
可拍照诊断的证据；已缓存的受保护书籍不再因为整片擦除而失效。

## 修复：打开书籍时的崩溃（0.8.1 / 0.8.2 共有的根因）

打开正文含生僻字的书时，阅读器会惰性从内部 flash 取字形；渲染任务的栈在 PSRAM，
而 0.8.1 起这条读取路径没有栈守卫，于是触发
`assert failed: … esp_task_stack_is_sane_cache_disabled()` 并重启——用户看到的是
先弹「DRM 保护文件」提示、紧接着崩溃。现在**所有内部 flash 访问都必须先问
`memory::guardInternalFlash(site)`**，拒绝时返回「未知」而不是「不存在」。

同一类问题的另一半：空 `std::function` 在 `-fno-exceptions` 下没有落点，直接
`std::terminate → abort()`（就是那句只有 PC 的短崩溃）。所有裸回调调用已收进
`callbacks::call/callOr`，门禁保证全树 0 处裸调用。

## 新增：崩溃自证

- 故障码台账：会导致崩溃/重启/卡死的拒绝被记成语言中立短码（`PNC-01`、`STK-08`、
  `CBK-01`、`TSK-03`、`PNL-02`、`STR-01`），存进 16 槽 RTC 环，**能活过一次崩溃重启**。
- 崩溃屏：第二行直接给 `fault=…` 与断言的 `file:line`，内容超出一屏时可翻页（不再静默截断）。
- `crash_report.txt`：每个码一句解释 + 跳过回调的站点名；`CMD:FAULTS` 可在串口重放同一份内容。
- 新增异常钩子：把 `std::terminate`/`new` 失败的 PC 变成具名异常 + 出事时所在的界面与阶段。

## 修复：整片擦除后旧书打不开

书的 `.key` 原先用 NVS 里的随机设备密钥包裹，而「擦除设备」刷写会替换该密钥，
于是所有已缓存书籍都变成「DRM 保护文件」。现在密钥绑定**硬件身份**（eFuse MAC），
擦除刷写不再使书失效；旧格式的 key 在第一次成功打开时自动迁移。真正无法解密的书会
说明原因，并给晋江书籍一个「重新缓存」入口，返回后阅读器自动重试打开。
章节缓存同步升级为 v3（同一硬件派生），v1/v2 会在首次读取时重封。

## 其它

- 联网后缺字方框：网络回收到的那块内存会被**配对归还**，字体状态自动恢复。
- 设置：每个设置项都归入具名分组；「字体与词典」「更新」改为枢纽页；工具页显示整个应用目录；
  「应用 / 设备插件 / 网页插件」三类术语彻底分开。
- 内存账本：只读，记录分配归属，不改变任何行为（诊断用）。

## 升级说明

- 0.8.1 及以后可直接 OTA；**本次必须同时更新数据包与 PDF 引擎**：语言包键集合变化，
  且应用体积变化会移动 XIP PDF 引擎的固定地址，二者需要成对更新。官网完整安装始终可用。
- 0.7.0 及更早版本仍需完整安装。
- 若设备做过整片擦除，旧书需要重新缓存一次；此后不会再因擦除失效。

## 验证

- 构建：`readpico` 与发布目标 `readpico_pdf_jjwxc` 均通过；`verify_release_artifacts --release`、
  数据清单与数据包头逐字节核对、`SHA256SUMS`。
- 宿主：故障环（72 项 + 5 变异）、栈守卫（23 项 + 4 变异）、回调守卫（29 项 + 5 变异）、
  断言/格式与三套静态门禁全绿；断词三趟摘要不变。
