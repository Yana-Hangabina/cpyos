# 脆皮鸭 CPYOS 0.6.2

让「检查更新」先走 GitHub 官方，并把线路探测从七条降到三条，缩短等待时间。基于 0.6.1，面向 **Read Pico（小纸 Pico，RDP-G01-W）**。

## 改进

- **GitHub 官方优先**：清单先请求 `github.com/.../releases/latest/download/readpico-ota.json`，失败后才依次尝试 gh-proxy、GitHub Pages 与 ghfast，每条线路有独立的短超时。
- **固件下载不再逐条探测七个镜像**：只测 GitHub 直连、刚成功取到清单的同一条镜像线路，以及清单给出的地址；最多三次探测。
- **数据包清单走同一条线路**：`readpico-packs.txt` 继续使用刚成功的线路，失败时才换备用线路，单次请求上限也缩短。
- 日志会打印每条线路的耗时，便于判断当前网络卡在哪一步。

## 升级说明

- 0.6.0 / 0.6.1 可直接设备 OTA；数据包与 0.6.1 相同，不需要完整安装。
- 0.2.1 及更早版本仍请用官网网页刷机升级一次。
- 本次没有改分区表、数据包布局或语言包键集合。

## English

Makes the update check try GitHub first and cuts route probing from seven mirrors to three. Based on 0.6.1, for **Read Pico (RDP-G01-W)**.

**Improvements.** The manifest is requested from `github.com/.../releases/latest/download/readpico-ota.json` first; gh-proxy, GitHub Pages and ghfast follow only if it fails, each with its own short timeout. Firmware download no longer probes seven mirrors: it measures GitHub direct, the mirror route that just served the manifest, and the advertised URL (three probes at most). `readpico-packs.txt` reuses the route that just worked and falls back only on failure. Each route's elapsed time is logged.

**Upgrade.** 0.6.0 and 0.6.1 can use device OTA directly. The data packs are unchanged from 0.6.1; no full install is needed. Devices on 0.2.1 or older still need the web flasher once. This release does not change the partition table, data layout or language key set.
