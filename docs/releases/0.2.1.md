# 脆皮鸭 CPYOS 0.2.1

升级路径修复版本，基于 0.2.0。面向 **Read Pico（小纸 Pico，RDP-G01-W）**。

## 修复

- **浏览器升级清单同时写 app0 与 app1**：设备做过 OTA 后 otadata 会选中 app1，而网页刷机无法读取 otadata 判断活动槽。此前的升级 / 仅 app 清单只写 app0，会出现“显示写入成功，但设备仍从 app1 启动旧固件”的静默假成功。
- `manifest-upgrade.json`、`manifest-app.json` 现在写入两个 app 槽（`readpico-firmware.bin` 与 `readpico-app1.bin`，逐字节相同）以及五个数据包；`manifest-install.json` 保持首次安装语义（boot_app0 选中 app0）。
- 手动刷写文档与 `FLASH.md` 同步说明两个 app 槽。

## 升级说明

- **0.2.0 → 0.2.1**：数据包未变化，设备 OTA 只写 app 分区即可；浏览器升级请使用本版本的 `manifest-upgrade.json`。
- **0.1.x → 0.2.1**：语言包键数与译文有变化。中文与英文内嵌，app-only OTA 后中文界面完整；其余 33 种打包语言需用「从 CPYOS 升级」或完整安装包重写数据分区。
- 首次安装 / 从 CrossMux 切换仍使用网页刷机的「首次安装 / 恢复」。

## English

Upgrade-path fix, based on 0.2.0, for **Read Pico (RDP-G01-W)**.

**Fix.** The browser upgrade and app-only manifests now write **both app slots**. A device that has used OTA boots from app1, and the browser cannot read otadata to choose the active slot; an app0-only write looked successful while the device kept booting the old app1. `manifest-upgrade.json` and `manifest-app.json` now write `readpico-firmware.bin` (app0) and a byte-identical `readpico-app1.bin` (app1), plus the five data packs. `manifest-install.json` keeps the first-install semantics (boot_app0 selects app0). The manual-flash docs and `FLASH.md` describe both slots.

**Upgrade notes.** 0.2.0 → 0.2.1 keeps the data packs, so device OTA only writes the app partition; use this version's `manifest-upgrade.json` for a browser upgrade. From 0.1.x, the language pack changed: Chinese and English are embedded, so an app-only OTA keeps the Chinese UI complete, while the other 33 packed languages need the upgrade or full installer to rewrite the data partition.
